SHADOWBLOG — DEPLOYMENT AND TROUBLESHOOTING

Project layout
  server.js                 entire backend (storage adapters, REST API, boot)
  package.json
  public/index.html         blog markup only
  public/login.html         standalone sign-in page (/login)
  public/app.html           WhatsApp-style chat app (/app)
  public/css/*.css          base, blog, chat, social, login, app styles
  public/js/*.js            core, blog, chat, admin, social, gifs, app, login, shell
  render.yaml
  FIX.txt

Run locally
  Install Node 18 or newer, open a terminal in this folder, and run:
    $env:ADMIN_PASSWORD = 'your-strong-password'
    npm install
    npm start
  ADMIN_PASSWORD is required — without it the app prints a clear error and
  exits immediately. It is the password for the owner account "rube" (max
  72 UTF-8 bytes); no random password is ever generated or printed. Change it
  and restart to reset the owner password.
  Open http://localhost:3000. Without DATABASE_URL you will see a warning
  and the app will run in memory. Accounts, comments, room codes, sessions,
  and messages are all lost on restart in this mode.

Sign-in and chat app
  Visit /login to sign in or create an account. A successful sign-in opens
  /app, a WhatsApp-style layout with a chat list, Friends/Rooms tabs, a
  conversation pane, a details pane, and a notifications drawer. /app redirects
  to /login?next=/app when you are signed out. The blog's comment-box commands
  (/join, /rooms, /admin, /app) still work as before. Typing /app in any post's
  comment box opens the chat app; signed-out users go to /login?next=/app.

Social features and GIFs
  Logged-in users can search other users by username, send friend requests,
  and accept or decline incoming requests. Accepting creates a private DM
  room that appears in both users' room lists. Removing a friend deletes the
  DM room and its message history. Reactions (👍 ❤️ 😂 🎉 👀 🔥) and
  notification badges/toasts are available in the private chat.

  GIF search uses the Giphy API through a server-side proxy. Set
  GIPHY_API_KEY to enable it; the key never reaches the browser. With no key,
  /api/gifs/config reports configured:false and the GIF button is hidden —
  every other feature still works. Get a free key from the Giphy developer
  portal and add it as an environment variable (the Render Blueprint declares
  it as sync:false). Search results are cached in memory for 5 minutes and
  only https media.giphy.com URLs are accepted.

Pre-deploy checklist
  [ ] ADMIN_PASSWORD is set in the deployment environment (required; the app
      exits immediately without it). Never commit it or a .env file.
  [ ] GIPHY_API_KEY is set only if you want the GIF picker; otherwise leave it
      unset — the button hides itself automatically.
  [ ] DATABASE_URL comes from the Render database (internal URL); local runs
      without it use memory mode and lose data on restart.
  [ ] render.yaml buildCommand = npm install, startCommand = npm start,
      healthCheckPath = /health, web service and database in the same region.
  [ ] npm start works locally with the same env vars (see Run locally).
  [ ] No test scripts, screenshots, dumps, or .env files are in the repo.
      `.md` docs (AGENTS.md, README.md) and FIX.txt are kept.

Deploy with a Render Blueprint
  1. Push the project, including public/index.html and public/css + public/js,
     to your Git repository.
  2. In the Render Dashboard, choose New > Blueprint and select the repo
     and branch containing render.yaml.
  3. When asked for ADMIN_PASSWORD, enter a strong password and keep it in
     a password manager (bcrypt accepts up to 72 UTF-8 bytes).
  4. Deploy. The Blueprint creates both free resources in Singapore and
     fills in DATABASE_URL from the database automatically.
  5. Open the deployed URL. Append /health to check the mode; on Render
     the response should be "ok - mode: RENDER_DB". This endpoint checks
     the web process, not the database connection. Check logs if the app
     remains on the wake-up banner.

Deploy manually
  1. Create a free PostgreSQL database in Render first. Choose your region.
  2. In its Connect/Info section, copy the INTERNAL Database URL, not the
     External Database URL. Treat both URLs as credentials.
  3. Create a free Web Service from the repository in the SAME region.
     Use Node, build command "npm install", start command "npm start",
     and health check path /health. Leave Root Directory blank if the
     files are at the root of the repo.
  4. In the web service's Environment settings, set DATABASE_URL to that
     internal URL, ADMIN_PASSWORD to your owner password, and NODE_ENV
     to production. Deploy the service.

Use the private chat
  Type /admin into any blog comment field and submit. Log in as rube with
  the ADMIN_PASSWORD you set. The Admin Panel opens with Admin Chat. On
  mobile, tap Back to chat to see the chat pane. Command words and codes are
  case-insensitive. Share a room code privately; a friend types /join CODE in
  a comment box, then registers or logs in. /rooms lists your previously
  joined, active rooms. /logout signs out. /app opens this app from the blog.

ECONNREFUSED, connection timeout, or unexpected MEMORY_NO_DB
  DATABASE_URL is missing, wrong, or pointing at an unreachable database.
  Confirm the database is still running, that both resources are in the
  same region, and that the web service has the current INTERNAL URL.
  Correct it and redeploy. Missing DATABASE_URL starts memory mode;
  an unreachable configured database does not silently switch to memory.

ENOENT or "index.html not found - Upload public/index.html"
  Verify the spelling and casing of public/index.html. Make sure it was
  pushed under the public folder next to server.js, and that the service
  uses the correct branch and root directory. Redeploy after fixing it.

Cold starts
  After 15 minutes idle the free web service sleeps. The first request
  can take 30–60 seconds; Render may show its own page before it can serve
  ShadowBlog's HTML. Once the page loads, ShadowBlog shows its wake-up
  banner and retries startup requests with backoff. Optionally monitor
  /health with UptimeRobot every 10 minutes if your plan allows that
  interval. Render's free web services share 750 free instance-hours per
  workspace per month; keeping an instance awake consumes those hours.

Free PostgreSQL retention and expiry
  Chat keeps the newest 500 messages per room, and comments the newest
  200 per post; both delete entries older than 14 days. Free Postgres
  expires after about 30 days. Back up before the dashboard's expiry date.

  Use the EXTERNAL URLs for backup/restore from your own machine (the
  internal URL is for the deployed service). With PostgreSQL client tools
  installed, enter the old External URL securely into OLD_EXTERNAL_URL,
  then run:
    pg_dump --format=custom --no-owner --no-acl --file=shadowblog.dump "$OLD_EXTERNAL_URL"
  Create a replacement database and set NEW_EXTERNAL_URL to its External
  URL. Restore to that empty database before starting the web service
  against it, so the app does not create or seed tables first:
    pg_restore --no-owner --no-acl --file=shadowblog-restore.sql shadowblog.dump
    psql "$NEW_EXTERNAL_URL" -X --set=ON_ERROR_STOP=1 --single-transaction --file=shadowblog-restore.sql
  Update DATABASE_URL to the replacement INTERNAL URL and redeploy. For a
  Blueprint, also update its database reference if the resource name
  changed. Use the Dashboard's backup/export feature instead if your
  plan offers it. Keep dumps private; they contain application data and
  password hashes. Delete temporary exports or secure them when done.

Forgot the admin password
  Set a new ADMIN_PASSWORD in the web service's Environment settings and
  redeploy. Startup updates the owner password in the database. The
  username stays rube. ADMIN_PASSWORD is authoritative on every start:
  changing it resets the owner password on the next deploy. Redeploying with
  the same value leaves the stored hash untouched.
